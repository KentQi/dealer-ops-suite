# 合同包审阅协议

合同包 = 主合同 + 防窜货附加协议 + 价格/出货政策文件。审阅分两层，**不能互相替代**：

1. **确定性审阅**：`review_contract_package.py` 检查必填、格式、日期、金额、比例、目标、返利、保证金、附件日期、政策表三类问题。输出带字段与当前值的「需确认项」。
2. **LLM 语义审阅**：由当前 harness 的模型阅读合同包原文，找条款矛盾、单方义务、定义缺失、罚则不可执行、续约/解除冲突等语义风险。LLM **只产出需确认项，不直接改合同**。

## 确定性审阅

```bash
python3 "$SKILL_DIR/scripts/review_contract_package.py" \
  --spec "$SKILL_DIR/scripts/spec/jx.json" \
  --values /tmp/cfj-values.json \
  --fc-spec "$SKILL_DIR/scripts/spec/fc.json" \
  --fc-values /tmp/cfj-fc-values.json \
  --policy "<价格政策表.xlsx>" \
  --out /tmp/合同审阅.json --md /tmp/合同审阅.md
```

- 退出码 `1` = 存在 `blocker`，**不得进入写入**。
- `high` 不自动阻断，但必须逐条让用户确认。
- `medium` / `low` 作为提醒，不能静默丢弃。
- 没有提供 `--policy` 或 `--fc-values` 时，报告会明确写“未覆盖”，不能把“没查”说成“没问题”。

## LLM 语义审阅

### 输入

给模型：

- 主合同、附加协议、价格/出货政策的**原文**（docx/pdf 文本，保留条款编号）；
- `spec` 与 `values.json`（用于核对填写值，不替代原文）；
- 确定性审阅结果（避免重复报同一问题）；
- 用户已确认的口径（`_口径确认.json`，如有）。

### 审阅维度

按以下顺序逐项过，找不到问题也要在报告里写“未发现”：

1. **合同包一致性**：三份文件的主体名称、税号、合同编号、期限、产品范围、结算方式/基数是否一致。
2. **商务条款内在矛盾**：价格、返利、保证金、账期、异议期、签回期、目标之间是否互相打架。
3. **价格与结算**：价格政策有效期是否覆盖合同期；同一产品同一期间是否出现两个价格；贴花/返利基数与结算基数是否一致。
4. **指标与返利**：季度/月度目标、最低达成、返利触发条件、未达成后果是否写清；目标合计是否与年度口径一致。
5. **防窜货附件**：罚则是否可执行、是否与主合同解除权/保证金条款衔接、是否有举证与认定程序。
6. **权利义务平衡**：是否只有乙方义务没有甲方义务；是否缺少验收、退换、质量、交付、不可抗力等基本条款。
7. **定义与歧义**：`合理`、`及时`、`严重`、`重大` 等无标准词；同一术语在不同文件定义不同。
8. **期限、续约与解除**：自动续约、单方解除、终止后的库存/价款/返利处理是否完整。
9. **可执行性**：罚则是否有计算基数、上限、支付期限；争议解决条款是否明确。

### 输出 schema

```json
{
  "findings": [
    {
      "category": "法律/条款风险",
      "severity": "high",
      "field": "第七条第 1 款",
      "label": "季度目标",
      "message": "季度目标只写了“完成目标”，没有写未完成时的后果，也没有写是否影响返利。",
      "evidence": {
        "document": "主合同",
        "clause": "第七条第 1 款",
        "quote": "乙方应完成季度目标。"
      },
      "ask": "请确认未完成季度目标时是否影响返利或合同续签。"
    }
  ]
}
```

合并到确定性报告：

```bash
python3 "$SKILL_DIR/scripts/review_contract_package.py" \
  --spec ... --values ... --fc-values ... --policy ... \
  --llm-findings /tmp/llm-findings.json \
  --out /tmp/合同审阅.json --md /tmp/合同审阅.md
```

### 严重度

| 级别 | 含义 | 处理 |
|---|---|---|
| `blocker` | 客观缺失/矛盾，继续写会产出错误合同 | 必须修正后重跑 |
| `high` | 可能改变权利义务或结算结果，需要用户判断 | 逐条确认；未确认不得说“审阅通过” |
| `medium` | 表述不清、提醒项、可能遗漏 | 告知用户，可留痕后继续 |
| `low` | 文字/格式建议 | 可延后 |

### 硬规则

1. **每条结论必须有原文引用**：文件 + 条款号 + 原文。没有原文的推测不得写入。
2. **不出法律意见**：写“需确认/可能风险”，不写“无效/违法/一定败诉”。
3. **不自动改条款**：只给问题与追问；修改由用户决定、由填合同流程执行。
4. **不重复报确定性项**：数字、日期、格式已经由脚本查过的，不重复堆给用户。
5. **找不到就写“未发现”**：不能因为没看到就默认没问题；也不能编造问题凑数。
6. **未提供文件就写“未覆盖”**：没看到价格政策，就不能说价格政策没问题。
7. **用户不确认，不算通过**：报告结论只能是“待用户确认”，不能替用户签字。
