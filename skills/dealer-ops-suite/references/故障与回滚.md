# 故障与回滚

本文件补充 SKILL.md 的配置、报错与回滚细节。先按业务类型排查：铺货代销走 `recon_engine.py`，月结买断走 `monthly_recon_engine.py`，直接买断不进入对账引擎。

## 输出与写入约定

- `load_master.py`：stdout 输出单行 `RECON_CFG` JSON；`--cfg-out` 原子写入**同一份**配置。参数、主档或目录错误写 stderr 并非 0 退出。
- 两个对账引擎：成功时输出工作簿、同目录 `_结算结果.json` 与 `_回写.json`；失败不得留下可误当作正式结果的半成品。过程日志与中文原因写 stderr。
- `apply_v17.py`：铺货附表保存后刷新 `_结算结果.json` 的工作簿路径与 SHA-256，保留 `rule_result`；月结不走该脚本。
- `make_review_packet.py`：结果凭证路径或哈希失效时直接失败；主档与源表也须匹配出账快照，不生成半成品复核包。
- `apply_review.py`：默认 dry-run；`--apply` 必须提供 `--packet` 才落盘，`--check` 校验复核锁。校验失败、清单不通过却标为通过或报告不通过均返回非 0。
- `writeback_ledger.py`：默认 dry-run；`--write` 必须提供 `--from-json`，核对已复核结算结果、主档快照及 pre/post 哈希链后才备份并原子写入主档「期间」表。
- 主档写入、映射与合同编辑均先 dry-run／审阅；不要通过手工改锁、哈希或结果 JSON 绕过门禁。

## RECON_CFG 结构

推荐让配置落盘后再导出，避免终端截断，也供 `apply_v17.py --cfg` 使用：

```bash
python3 "$SKILL_DIR/scripts/load_master.py" "<_主档.xlsx>" \
  --period 202610 --asof 2026-11-02 --cfg-out "<本期目录/RECON_CFG.json>"
export RECON_CFG="$(cat "<本期目录/RECON_CFG.json>")"
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `business_type` | 是 | `consignment` / `monthly_buyout`；由唯一覆盖本期的合同显式路由 |
| `party_a` / `party_b` | 是 | `name/tax` 等主体信息；缺失按脚本告警或 `--strict` 阻断 |
| `contract` | 部分 | `no/method/basis/pay_day_text/objection_days/signback_days/price_annex/buyout_date/payment_due_date`；月结的买断日和付款截止日必须明确且分别登记 |
| `period` | 是 | `start/end/asof` 及显示字段；付款日期无法识别时保持未登记，不默认次月 5 日 |
| `bank` | 是 | 甲方收款账户；`account_name` 缺省取甲方名称 |
| `base_dir` | 是 | 本期目录绝对路径；指定目录不存在即停止，不回退其他月份或客户根目录 |
| `sources` | 是 | 铺货核心角色 `jia/sales/inventory`，另有回加、批次等可选角色；月结核心角色 `receipts/returns/sales` |
| `master_path` | 是 | 主档绝对路径，价格、贴花、SKU 与合同取数来源 |
| `original_sales` | 视退货 | 历史销售流水，来自 `--original-sales <JSON>`，用于原销售价／贴花追溯 |
| `original_receipts` | 视月结退货 | 历史签收流水，来自 `--original-receipts <JSON>`，用于原签收价追溯 |
| `out_file` / `overwrite` | 否 | 输出路径与显式覆盖开关；不要覆盖历史对账单 |
| `verify_notes` | 否 | 自定义「源数据核对记录」 |
| `mapping` | 否 | 经用户确认的 `_数据映射.json`，结构见 `数据映射与结构探查.md` |
| `koujing` / `v17` | 铺货相关 | 已确认口径与附表配置；`--allow-legacy` 只供历史铺货只读复核 |

排错时可设 `RECON_DEBUG=1` 查看缺配置细节。不要手填一份与 `--cfg-out` 不同的配置来运行附表或引擎。

## 入口、主档与源文件

| 报错或现象 | 处理 |
|---|---|
| `RECON_CFG` 缺失、非法或顶层不是对象 | 重跑 `load_master.py`；不要用内置示例或测试目录兜底 |
| `[找不到主档]` / `[无法读取主档]` | 核对路径与文件；`.xls` 先另存为 `.xlsx`，不要修改原始合同或源导出 |
| 多份合同完整覆盖本期 / 没有合同覆盖本期 | 补全或整理合同起止和业务类型，保证本期唯一合同；不要任选一份 |
| 指定期间目录不存在、提示不会回退 | 创建正确期间目录或显式 `--base`；不要借用最近月份数据 |
| `[缺少源文件]` | 铺货核对 BIP 期初、销售／退货、库存；月结核对签收、退货、乙方动销，并检查 `sources` 角色与文件名 |
| 月结缺买断日或付款截止日 | 在主档分别补完整 `YYYY-MM-DD`；不得合并、默认或由 `asof` 推导 |
| 铺货付款日无法识别 | 从合同补登记，或明确 `--pay YYYY-MM-DD`；不填次月 5 日 |
| 表名、表头或列不存在 | 先 `inspect_schema.py`，再由用户逐项确认映射；不要按列位置猜 |
| 数值为布尔值、空值、文本、NaN 或无穷大 | 修正源数据；引擎不静默转换 |
| 商品未明确登记结算类／非结算类 | 在主档 SKU 表补全；月结非结算商品会过滤并记录 `ignored_non_settlement_barcodes`，未知属性仍阻断 |
| 销售／签收／退货流水缺条码、日期或流水号 | 补齐原始依据；不得按品名或退货日价格猜算 |
| 重复流水号 | 去重并确认业务含义后重跑；退货追溯和金额计算不会继续 |

## 业务规则阻断

`settlement_rules.py` 用 `RuleViolation(code, message)` 表示可机器处理的阻断项；引擎通常输出 `结算规则阻断[错误码] 原因`。常见错误如下：

| 错误码 / 文案 | 含义与处理 |
|---|---|
| `DIRECT_BUYOUT_NOT_RECONCILED` / `UNKNOWN_BUSINESS_TYPE` | 直接买断不进对账；其他未知类型须回主档明确业务类型 |
| `NO_UNIQUE_RATE` / `RATE_COVERAGE_GAP` / `OVERLAPPING_RATE_INTERVALS` | 合同价格或贴花断档、重叠、缺生效日；按条码与业务日修复版本，不取均价 |
| `INVALID_RATE_INTERVAL` / `NEGATIVE_RATE` / `INVALID_NUMBER` | 生效区间或数值非法；修正主档，不默认 0 |
| `MISSING_BUSINESS_DATE` / `TRANSACTION_OUTSIDE_PERIOD` | 流水缺日期或不属于本期；换正确流水或期间 |
| `ORIGINAL_PRICE_REQUIRED` / `MISSING_ORIGINAL_REFERENCE` | 退货缺原流水或明确原价；铺货补原销售，月结补原签收，不按退货日价替代 |
| `ORIGINAL_BARCODE_MISMATCH` | 退货与原流水条码不一致；先核对退货关联，不强行冲减 |
| `ORIGINAL_DECAL_UNKNOWN` | 原销售是否已计提贴花未知；补「是／否」及原标准依据，不默认冲或不冲 |
| `VARIANCE_AUTHORIZATION_REQUIRED` / `VARIANCE_AUTHORIZATION_PERIOD_MISMATCH` | 盈亏纳入缺本期起止授权，或把其他期间授权继承到本期；补逐期单次授权，否则保持只列示 |
| 数量勾稽不成立 / 盈亏列示金额复算不一致 | 回查 BIP 期初、销售、退货、库存、回加与期末合同价；禁止用调价价差或其他倒挤项凑平 |
| 贴花合计复算不一致 | 铺货核正常销售期末标准与退货原标准；月结核动销日标准；不得把签收货款数量代替动销贴花数量 |

**任何盈亏都不是出账阻断阈值。** 盈亏为正表示短缺、为负表示盘盈；先出对账单供双方核对。只有缺库存、缺价格、缺原价等事实依据时才阻断相应计算。盈亏列示默认不进结算总额，也不设置自动放行开关。

## 复核与结果哈希

| 报错或现象 | 处理 |
|---|---|
| `[结算结果凭证无效] …绑定的是另一份工作簿` | 使用与工作簿同目录、同一次出账的 `_结算结果.json`，不要复制其他期间凭证 |
| `工作簿在结算后已变更，_结算结果.json 已过期` | 普通编辑后重新出账；仅铺货 v17 附表保存时由 `apply_v17.py` 正式刷新路径与哈希，再生成复核包 |
| `rule_result` 缺失、业务类型不一致或无效 | 重跑对应引擎；不要手写规则结果 |
| `--check` 报复核无效 / 锁或复核表缺失 | 重新生成复核包 → R1–R10 → `--apply` → `--check`；不得手工造锁 |
| `workbook_sha256` 不一致 | 报告基于旧版本，按当前工作簿重新复核 |
| checklist 缺 R1–R10 / verdict 与 findings 矛盾 / summary 为空 | 补全报告并修正结论；不得把阻断降级来交付 |
| 历史工作簿没有结果凭证 | 只能做历史标签扫描并披露限制，不冒充本期逐笔规则复核 |
| `复核包引用的规则底稿不存在：<文件名>` | 侧车 `*_rule_result.json` 未随复核包归档／迁移；找回侧车与复核包同放，或重新生成复核包，不可只带包走 |
| `规则底稿与复核包不一致` | 侧车在生成后被修改或替换；用原 `_结算结果.json` 重新生成复核包（不可手工修补侧车凑哈希） |

## 合同双门禁与待办

- 写前缺 `--approve-write` 凭证、存在 blocker、high 未按 finding id 登记 `status/note/owner` → 不填写合同。
- 最终放行缺三份文件、哈希变化、findings 指纹或 high 处理记录变化 → `verify_fill.py` 失败；重新审阅并放行，不改凭证凑哈希。
- 工作日待办必须提供覆盖年份的法定节假日及调休日历；无日历时 `estimated=true`，不能当精确承诺日。
- 付款截止日只有合同明确登记顺延／提前规则才调整；否则保留原日期。
- 待办只提醒，不自动算返利、扣保证金、认定窜货或创建定时任务。

## 回写与输出保护

- 回写先用 `--from-json <_回写.json>` dry-run，再 `--write`。正式写入要求同目录 `_结算结果.json`（或 `--result`）与有效复核记录（或 `--review-dir`）：回写值逐字段匹配结果内嵌 `writeback`，目标主档路径及哈希匹配出账快照，锁 pre 哈希匹配出账工作簿、当前工作簿匹配锁 post 哈希，报告结论为通过／有条件通过。失败时不写主档。
- 同期间更新原行，不追加重复行；期间重复时先人工合并。首次回写后主档哈希自然变化，完全相同的重复操作可幂等 noop；若还要改数，必须重新出账和复核。
- 净退货可产生负结算数量、负结算金额和负贴花，回写保留符号；只有 BIP 期初数量／参考金额要求非负。不得为通过校验把负数改成正数或 0。
- 月结写回中的 operational zero 只用于数值字段落盘，不代表存在 BIP 期初或库存盈亏；复核仍以 `rule_result` 为准。
- 输出已存在时按引擎提示改名或显式覆盖；正式交付前确认没有覆盖历史版本。
- 写盘失败先关闭 Excel／WPS，再检查权限和磁盘；临时文件清理后重跑，不交付半成品。

## 回滚

| 对象 | 回滚方法 |
|---|---|
| 主档 `_主档.xlsx` | 从 `_备份/` 或 `_主档.bak-YYYYMMDD-HHMMSS.xlsx` 取上一版覆盖；保留当前故障副本供比对 |
| 对账工作簿 | 优先保留历史版本并重新出账；不要只改 `_结算结果.json` 来适配旧工作簿 |
| 铺货 v17 附表 | 用变更前工作簿及其配套结果凭证恢复，再重跑附表；最终重新生成复核包与复核锁 |
| 确认单与映射 | `_确认记录/` 按时间戳归档；从已确认版本恢复，重新 dry-run |
| 复核记录 / 复核锁 | 数据变更后整组重做，不手工删锁或改哈希；旧报告作为历史留痕 |
| 合同成品 | 从合同编辑留痕／备份恢复后重新执行写前审阅、三文件放行与 `verify_fill.py` |
| 台账回写 | 取本次 `writeback_ledger.py` 写前备份恢复；修正 `_回写.json` 来源后重新 dry-run 和写入 |

回滚后必须重跑对应引擎与复核，不得把回滚前的复核锁视为仍有效。

## 三条硬规矩

1. **不用内置兜底路径**：无有效配置即停止，避免测试结果进入客户目录。
2. **不在客户目录做实验**：试跑用独立工作区与 `--out`，源导出和合同原件不改。
3. **写前必看 dry-run／审阅**：主档、映射、合同、复核与回写均按各自门禁执行。
