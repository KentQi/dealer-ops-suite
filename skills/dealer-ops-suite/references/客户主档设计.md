# 客户主档设计

主档固定七表，分两层：**对账必需层**（主体／合同／价格／SKU／期间／贴花）与**履约提醒层**（履约条款）。只登记关键值和原文依据，不搬运整份合同。

## 1. 设计原则

1. **合同价格政策是单价权威源。** 铺货的 BIP 导出只提供本期期初数量；月结按签收流水结货款。
2. **时间变化必须留版本。** 价格、贴花以“商品条码＋生效起”为主键，月中调价为两行，旧行不覆盖。
3. **条码是匹配键。** 品名只用于展示与别名反查，不用品名猜价格或原流水。
4. **合同按期间选择。** 必须只有一份合同完整覆盖对账起止日；零份或多份都阻断。
5. **期间目录不可回退。** 指定月份目录不存在即停止，不借最近月份或客户根目录的数据。
6. **提醒与执行分离。** 履约条款用于提醒，不自动算返利、扣保证金或认定窜货。

## 2. 文件布局

```text
客户目录/
├── _主档.xlsx
├── _口径确认.json             # 铺货正式出账需要
├── _数据映射.json             # 可选，经用户确认的源表结构映射
├── 202610/
│   ├── 甲方-BIP期初.xls        # 铺货
│   ├── 乙方-销售数据.xlsx      # 铺货销售／退货
│   ├── 乙方-库存.xlsx
│   ├── 乙方-签收.xlsx          # 月结
│   ├── 乙方-退货.xlsx
│   ├── 乙方-动销.xlsx          # 月结，仅用于贴花
│   └── RECON_CFG.json
└── _备份/
```

同一客户若两种模式并存，合同必须能用期间与唯一有效合同规则消歧；直接买断只登记，不进入对账。

## 3. 对账必需层

### 3.1 `主体`

字段：角色、名称、统一社会信用代码、地址、联系人、电话、开户行、账号、户名。

甲乙方名称是必要信息；甲方收款信息进入对账单。缺失不会用演示值替代。

### 3.2 `合同`

关键字段：

| 字段 | 用途与规则 |
|---|---|
| 合同编号 | 对账与回写索引，必填 |
| 业务类型 | 铺货代销／月结买断／直接买断；直接买断不进引擎 |
| 起始／终止 | 必须完整覆盖对账期间 |
| 结算方式／结算基数 | 对账说明与合同复核 |
| 付款日 | 铺货付款期限；能提取明确日号才用于 `--pay`，不默认次月 5 日 |
| 买断日 | 月结必填，与付款截止日分开 |
| 付款截止日 | 月结必填的完整日期；铺货有明确约定时也可登记 |
| 异议期／签回期 | 工作日条款，进入待办与对账说明 |
| 付款顺延规则 | 仅合同明确约定时填写；否则不调整付款截止日 |
| 价格附件 | 指向价格政策版本 |
| 原文依据／来源文件／来源位置 | 支持回查，不用摘要替代原件 |

合同更新必须绑定合同编号，例如 `合同.付款日@合同编号=HT-1`。多主键命中时拒绝取第一行。

### 3.3 `价格`

字段：商品条码、商品名称、供货价、生效起、生效止、零售价、依据文件。

- 生效起必填；生效止为空表示持续有效。
- 同一 SKU 同日必须只有一条有效记录，重叠、断档、非法值均阻断。
- 铺货正常销售逐笔按销售日取价，退货按原销售价；月结按签收日取价，退货按原签收价。
- 合同附件价格经确认后可按合同期生效；调价政策必须有明确生效日。

### 3.4 `SKU`

字段：商品条码、标准品名、乙方品名别名、规格、单位、箱规、结算属性、备注。

`结算属性`只能是`结算类／非结算类`。非结算类流水排除并留痕；空值、未知值或同码属性冲突均阻断，不默认全部结算。

### 3.5 `期间`

字段：期间、合同编号、业务类型、数据基准日、期初数量／金额、结算数量／金额、差异数量／金额、贴花金额／兑付方式、买断日、付款截止日、对账单编号、状态、备注。

- 由 `writeback_ledger.py` 回写；引擎不拿上期期末强制约束本期 BIP 期初。
- 月结的期初数量／金额、差异数量／金额使用工作流写回值 `0`，不代表存在 BIP 期初或库存盈亏。
- 净退货可形成负结算数量、负金额、负贴花，必须保留符号。
- 同一期间更新原行，不追加重复行；先 dry-run，再 `--write`，写前自动备份。

### 3.6 `贴花`

字段：商品条码、商品名称、贴花标准、生效起、生效止、依据文件、备注。

- 铺货正常销售按对账期末日标准；退货只有原销售已计提时才按原销售标准冲减，未计提不冲，未知阻断。
- 月结按每笔乙方动销日期取标准；动销不减少买断货款。
- 无奖励可显式登记 `0`；没有贴花表时按对应引擎规则处理，不伪造标准。
- 盈亏不参与贴花；贴花兑付方式不由模型替用户决定。

## 4. 履约提醒层：`履约条款`

字段：合同编号、条款类型、关键值、原文依据、来源文件、来源位置、提醒状态、备注。

可登记月度／季度指标、返利、保证金、防窜货约束等，但只保留计算或提醒所需的关键值及原句。`make_todos.py` 据此生成本地 `_待办.json`：

- 工作日计算需要法定节假日及调休日历；调休上班日优先于周末／节假日。
- 无覆盖年份日历时，待办标记估算，不给伪精确日期。
- 付款待办保留合同原截止日；仅明确的顺延／提前规则可调整。
- 不自动创建定时任务，不自动执行返利、扣款或违约认定。

## 5. 维护与常见错误

- 新政策追加“条码＋新生效起”行，并正确封闭旧行；不得覆盖历史价。
- 新字段写入前整单 dry-run；被拒绝字段不会留下只有主键的残行。
- 不用品名匹配退货原价，不用退货日价格替代原价。
- 不把月结乙方动销当作买断货款的减项。
- 不将付款日、买断日、付款截止日合并为一个字段。
- 结构漂移走 `inspect_schema.py → 用户确认 → apply_mapping.py`，不改源导出、不猜列。
