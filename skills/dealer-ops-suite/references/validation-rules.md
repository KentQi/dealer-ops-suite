# 校验规则

`scripts/build_plan.py` 按字段的 `vtype` 逐项校验，再跑跨字段一致性。下表是**判定口径**，脚本报错文案与之一致。

## 一、单字段

| vtype | 适用字段 | 规则 | 失败示例 |
|---|---|---|---|
| `company` | 乙方公司全称 | ≥4 字；不得有空括号；须以「公司/企业/商行/经营部/中心/店/厂/社/事务所/合伙」结尾 | `示例经销商` → 未以主体类型结尾 |
| `uscc` | 统一社会信用代码 | 恰好 18 位；字符集 `0-9A-HJ-NPQRTUWXY`（不含 I/O/Z/S/V）；GB32100 校验位 | `...XXXXX` → 校验位不匹配，末位应为「K」 |
| `person` | 联系人 / 法定代表人 | 2-15 字；不含数字与括号 | `张三2` → 含数字 |
| `phone` | 联系电话 | `1[3-9]\d{9}` 或 `0\d{2,3}-?\d{7,8}(-\d+)?` | `1380013800` → 位数不足 |
| `address` | 通讯地址 / 收货地址 / 签章页地址 | ≥8 字；含行政区划（省/市/区/县/旗/镇）；含详细指向（路/街/号/楼/室/层/栋/园区/仓） | `示例市示例区` → 未含门牌 |
| `region` | 经销区域-省 / -市 | 2-8 字；**不带**「省」「市」后缀（模板已有） | `示例省省` → 模板会变成「示例省省省」 |
| `channel` | 经销区域-系统 | 1-20 字；模板自动补「系统经销商」 | 不要再写「系统」二字 |
| `date` | 期限、签订时间、附件签署日 | 严格 `YYYY-MM-DD` 且为真实日期 | `2026-13-01` → 不是有效日期 |
| `percent_rebate` | 季度返利 / 年度返利 | 0 ≤ v ≤ 30，可含一位小数 | `35` → 超出 0-30 |
| `percent_any` | 动销保障比例 | 0 < v ≤ 100 | `0` → 应大于 0 |
| `amount_num` | 履约保证金-小写 | 1-9 位整数（元） | `1万` → 非整数 |
| `amount_cn` | 履约保证金-大写 | 仅中文大写字符；须与前面小写数值一致 | `10000元` → 应为「壹万元」 |
| `amount_wan` | 铺货额度 | 数字，>0，单位万元 | `-5` → 应大于 0 |
| `day` | 结款期限（每月几日前） | 1-28 的整数 | `31` → 超过 28 会碰到没有该日的月份 |
| `int` | 终端网点建设目标 | 非负整数 | `5.5` → 非整数 |
| `contract_no` | 主合同编号 | 四段式「品牌码-类型码-年份-序号」（品牌码 2 位、类型码 2 位、年份 4 位、序号 3 位）；可带 1 段 2 位扩展码，位置在年份之前；仅大写字母、数字、半角连字符；序号自 001 起；**类型码须等于合同类型（JX/DX/…）**、**年份须等于签订年份**；「待定」是唯一允许的中文占位 | `JX-2026-001` → 缺品牌码，应为 `DM-JX-2026-001`；`jl-jx-2026-001` → 小写不允许 |
| `text` | 通用短文本（当前未用于主合同编号） | 1-32 字 | 空 |

## 二、跨字段

| 检查 | 规则 | 级别 |
|---|---|---|
| 合同期限 | 起始日 **必须早于** 终止日 | 错误 |
| 签订时间 | 不得晚于合同终止日 | 错误 |
| 保证金大小写 | `amount_cn` 必须等于 `num2cn(amount_num)` + 「元」 | 错误 |
| 返利高低 | 年度返利不应超过季度返利的 2 倍 | 提示（可能填反） |
| 直辖市 | 省字段为 北京/上海/天津/重庆 时，`＿＿省＿＿市` 句式读感不佳 | 提示 |
| 目标合计 | 季度或月度分解合计金额 | 提示（仅参考，不自动平衡） |
| 附件日期 | FC-C1/C2 为**必填**，须显式传入 `YYYY-MM-DD`，**不自动推断、不默认跟随** | 缺失即报错（脚本） |
| 双合同一致 | 同一客户同时出 JX 与 DX 时，乙方名称、信用代码、联系人、地址、期限应完全一致 | **脚本不做**：代理人工逐项比对两份 values |

## 三、模板层校验（`scan_blanks.py`）

| 检查 | 判定 | 处置 |
|---|---|---|
| 锚点定位 | `index` 定位失效后按锚点第 N 次出现回退；仍找不到 → `MISSING` | 停止，报告缺失锚点 |
| 未登记空白 | 正文/表格中出现 `＿{2,}`、`【 】`、`(  )`、`XXX` 等，且不属于任何已知字段 | 停止，报告段落与上下文 |
| 甲方固定信息 | 名称、信用代码、账号、开户行必须存在 | 缺失即报警，不自动补 |
| 附件锁定表 | 违约金标准表内容与标准版逐格比对 | 不一致即报警，不自动改；扫描与验收共用 `check_locked_content()` |
| 扫描闸门 | 定位失败 / 配置错误 / 未登记空白 / 甲方信息缺失 / 锁定表不一致 | **退出码 1**（旧版恒 0，只打印文字，代理容易继续往下走） |

## 四、验收层校验（`verify_fill.py`）

| 检查 | 判定 | 退出码 |
|---|---|---|
| 计划可信（自洽） | 每条 op 必须带 `expect` 且与 `value` 精确相等 | 1 |
| **计划可信（重编译）** | 用 `--spec + --values + 原始模板` **重新编译**参考计划，逐条核对 `plan.ops`；同时校验规格内容指纹、值指纹、`source_values`。这是把「成品 == 计划」升级为「成品 == 计划 == 用户确认值」的关键一道 | 1 |
| 结构数量 | 段落数、表格数、文本单元数与模板一致（旧版只置标志位、未计入最终裁定，已修） | 1 |
| 文本越界 | 「原始模板 + 计划」哑演算结果必须与成品**逐字相同** | 1 |
| 字符格式 | 每段非空文字的字体/字号/粗细/斜体/下划线/颜色集合一致（原空白格填字不算） | 1 |
| 结构属性 | 段落对齐/缩进/间距、单元格底纹/边框/合并跨度、列宽、行高、分节与纸张 | 1 |
| 页眉页脚文本框 | 可见文字 **与域代码序列**（instrText / fldChar）一致 | 1 |
| 计划可定位 | 计划里任一条在模板文本上找不到 → 判定比对未完成 | 1 |
| 必填完整性 | 规格中 `required` 的字段状态不是 `FILLED`/`DEFAULT` 即视为未完成（含 `BLANK`/`MISSING`/`SPEC_ERROR`/`PARTIAL`，以及追加类无占位符字段）；目标表按设计允许只填季度或月度一档 | 3 |
| 残留占位符 | 成品中不得再有 `＿{2,}`、孤立 `＿`、`【 】`、`___` | 2 |
| 甲方信息 | 四项固定信息仍在 | 1 |
| 锁定条款表 | 附件一线上/线下窜货违约金标准表逐格与标准版一致 | 1 |
| 样式 / 文档属性 | `styles.xml`（含 `docDefaults` 默认字体）、`numbering.xml`、`docProps/core.xml` 语义指纹一致；忽略每次保存都会重写的时间戳与统计字段 | 1 |
| **包级完整性** | 部件清单必须与模板完全一致；除 `word/document.xml` 外每个部件按命名空间 URI 规范化后哈希一致（覆盖 settings / rels / Content_Types / app.xml / customXml / 页眉内表格图片 / 二进制媒体）；正文另比「结构骨架」（单元格内段落 pPr、域代码、图形与超链接引用） | 1 |
| 包可读性 | DOCX 包或关系引用损坏导致无法加载 → 判「比对无法完成」，不崩溃、不放行 | 1 |

> 注 1：`--spec` 与 `--values` 是**强制参数**。旧版可省略，等于关掉必填与指纹检查；第三轮已堵死。
> 注 2：比对基准**恒为原始模板**。旧版 `--base` 允许把上一轮成品当基准，实证可把任意越界文本
> 洗白成退出码 0（「`--base` = 成品 + 空计划」），且后续每一轮都会继承污染，故该参数已移除。
> 纠错 / 补填统一走累积全量 `values.json`。
> 注 3：`verify_fill.py` 会拒绝「模板与成品是同一个文件」的自比。
> 注 4：**信任根是 `values.json` 与 `scripts/spec/*.json`**。脚本只证明成品确实由这两者派生，
> 不证明这两份文件自身未被改过——它们必须由用户确认、由本 skill 维护。

## 五、写入层校验（`apply_fill.py`）

| 检查 | 判定 | 处置 |
|---|---|---|
| 匹配数量 | 需要的第 N 处必须存在 | 不足即中止整单 |
| 上下文校验 | `related_text` 去掉 `[ ]` 后须包含计划记录的上下文 | 不通过即中止 |
| 区间重叠 | 两条 `replace` 区间相交，或 `insert` 点落在别的替换区间内 | 中止，改用 `cell` 定位或加长 `find` |
| 重复执行 | 追加类操作：去空白的「锚点+值」整串比对 + 全文 `doc_find` 兜底（旧版只看 `related_text` 里 `]`+前 20 字，可被方括号/全角空格/窗口截断绕过） | 中止（防叠字） |
| 目标身份 | `--protect` **必给**，并与 `plan.template` 取并集；用 realpath + **inode** 比对（堵硬链接绕过） | 中止 |
| 池状态结构 | `get_pool_status` 返回非对象、或 `editors` 不是数组 | 中止，不再崩 AttributeError |
| 坐标与冲突 | 负坐标 / `end<begin` / 非整数；insert 冲突检测改用真实写入坐标 `r["end"]`；同一位置多个插入 | 中止 |
| 保存结果 | 失败文本、空回执、回执指向别处、mtime 未变、**内容哈希未变**、抽样写入值读不回 | 退出码 6，禁止交付 |
| 写入顺序 | 按文档位置从后往前写 | 保证未处理位置不漂移 |
| 计划可信（写入前） | 全量计划必须能由 `spec + values + 模板` 重编译复现 | 退出码 **7**，未落笔 |
| `.rejected` | 校验失败留存的排查文件不可当计划执行 | 拒绝 |
| 半写失败 | 输出「回滚三步」、禁止复用脏 `file_id` | 退出码 3 |

## 六、裁定原则

1. **错误（✗）阻断写入**：必须由用户修正或明确授权后才能继续，不允许"看着差不多就填"。
2. **提示（!）不阻断**：随对照表一并告知，用户认可即继续。
3. 校验脚本给出的"应有值"（如信用代码校验位、中文大写）只是**参考建议**，最终以用户确认为准；用户坚持的，按用户的填，并在交付说明里注明。
